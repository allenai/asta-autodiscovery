Reward computation, per-job rewards, and rollout groups

An RL run where the reward for each generated hypothesis is the Bayesian surprise of actually running it as an experiment. Below: how that reward is produced, how it's distributed per job, and the raw hypotheses each rollout group generated.

slime ↔ autodiscovery integration

POST /reward { hypothesis, dataset_id } → { reward, normalized_surprisal, posterior_mean }

The scorer runs as a separate HTTP sidecar, not inside the trainer:

  • Python isolation — slime needs 3.13, autodiscovery needs 3.10; HTTP decouples them.
  • No shared imports — slime speaks only the JSON contract above.
  • Different resource shape — GPU-bound training vs 48-way parallel CPU/API experiments.

the reward formula

reward = |normalized surprisal|
= |μpost − μprior| / theoretical_max
theoretical_max ≈ 0.64 → reward ≈ [0,1]

belief_change arm: |Δbelief| / 0.2
(÷ fixed width → often > 1)

3 Per-job hypotheses by rollout group

Each group = the 8 hypotheses one prompt generated. GRPO compares them within the group: the advantage (bar) is each reward minus the group mean — that's the learning signal. A group with zero spread gives no signal.
