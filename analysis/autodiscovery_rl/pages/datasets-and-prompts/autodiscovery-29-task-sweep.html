AutoDiscovery 29-Task Sweep

The POC pipeline run across the AutoDiscovery task registry (14 DiscoveryBench + 15 BLADE datasets): per task, three search policies spend the same query budget on conditional-association tests H(A,B | N), and four generation conditions (A: EDA→LLM · B: PC graph→LLM · C: PC results ranked · D: adaptive graph→LLM · E: entropy/MI summary→LLM) are judged against that task's expert gold hypotheses.

ConditionsWhat A–E actually differ in

Every condition produces k final hypotheses for the same dataset; they differ only in the evidence they see, who spent the statistical query budget, and whether an LLM writes the hypotheses. B vs A isolates the representation (Q1); D vs B isolates the search policy (Q2); C and E-ranked are the LLM-free floors of their evidence types.

Search phaseQuery spend and pruning across all tasks

Per-task budgets are 85% of the depth-limited hypothesis space, capped at 80. "PC used" below budget means PC-style pruning exhausted the reachable space early — the structural savings the proposal predicts. Task names link to that task's information-graph page.

Ranked baselinesE-ranked (mutual information) vs C (PC |r|)

Both are LLM-free top-k lists. Overlap is computed on endpoint pairs at k_eff = min(list lengths). "C-only cond." counts C findings that are conditional (|N| > 0) — inexpressible as a plain MI pair; "E cat." counts E pairs involving a categorical variable — outside C's reachable space (excluded from overlap). Low overlap on large-p tasks is mostly coverage, not nonlinearity: the PC budget can run out before finishing depth 0, while the MI scan always sees every pair.

Metric sensitivityThe same PC search under pearson, spearman, and MI

Identical PC policy, budget, and depth per task — only the CI-test oracle changes. "Queries" differ because the metrics prune at different speeds (a stricter oracle removes edges earlier and exhausts the reachable space sooner). Jaccard compares the surviving edge sets. See docs/test-taxonomy.md for when each metric is the right choice.

The part-mutual-information family (CMI · PMI · NPA · MPMI)

Scores from Zhao et al. (PNAS 2016, part mutual information) and Shang et al. (Bioinformatics 2021, NPA/MPMI), on binned distributions with rows subsampled to 2,000. All four reduce to MI when N = ∅. The papers threshold scores inside a PC algorithm; here each score gets a within-stratum permutation test (B = 60) so the whole family shares one calibrated verdict rule — which makes this family more conservative than the Fisher-z metrics above.

ReproduceCLI workflow

Everything on this page comes from the adaptive-hypothesis-discovery repo. Steps marked no API are pure local statistics; the rest use OPENAI_API_KEY (model AHD_MODEL, default gpt-5-mini).

Environment (once per shell):
export AHD_DATA_ROOT=/Users/sijial/workspace/asta-autodiscovery/_s3/autods/datasets
export AHD_GOLD_CSV=/Users/sijial/workspace/discoverybench/eval/answer_key_real.csv
export OPENAI_API_KEY=...          # LLM steps only
Generate configs for all registry tasks and validate them (no API):
uv run python scripts/gen_config.py               # keeps hand-curated configs; --overwrite to redo
uv run pytest -q                                  # core machinery tests
Search phase only across all tasks — what populated the search table above (no API):
uv run python scripts/run_sweep.py --jobs 6 --local-only
uv run python scripts/compare_ranked.py --k 15    # E-ranked vs C table above
uv run python scripts/compare_graph_metrics.py    # pearson/spearman/mi sensitivity table
uv run python scripts/compare_graph_metrics.py --metrics cmi pmi npa mpmi \
    --out results/pmi_family_comparison.json      # PMI-family table
Full pipeline (adds adaptive search, conditions A–E, judging; resumable — completed steps are skipped):
uv run python scripts/run_sweep.py --jobs 6       # status: results/sweep_status.json · logs: results/logs/
One task end-to-end, or a single stage by hand:
uv run python scripts/run_task.py --config configs/boxes.json
uv run scripts/run_search.py   --config configs/boxes.json --policy adaptive --budget 36 --max-depth 2
uv run scripts/run_generate.py --config configs/boxes.json --condition D --k 10 \
    --search-log results/boxes_adaptive_b36.json
uv run scripts/run_eval.py     --config configs/boxes.json results/boxes_gen_*_k10.json
Rebuild this page (and the per-dataset report pages):
uv run python scripts/build_sweep_report.py --out sweep_report.html
uv run python scripts/export_report_data.py --config configs/archaeology.json
uv run python scripts/build_report.py --name archaeology \
    --template scripts/report_template.html --out archaeology_poc_report.html

Method notes: partial-correlation CI tests (Fisher-z, α = 0.05); categorical variables are dummy-coded in conditioning sets and never endpoints. Budgets and depth are per-task (depth ≤ 2 below 10 endpoints, else ≤ 1). Gold sets: DiscoveryBench answer key for DBench tasks; relationships extracted from BLADE analyst annotations for BLADE tasks — tasks without either are search-only here. Generation and judging: gpt-5-mini; recall matching is judge-based and approximate. Single run per policy per task. Of the registry's 29 tasks, worldbank_education_gdp_indicators is excluded: its six indicator files hold 2 rows each (years as columns), so no usable analysis table exists in this framework.
