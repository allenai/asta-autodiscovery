Keyword reward sanity runs

Five GRPO runs on one archaeology prompt, 10 epochs, Qwen3.5-9B. Reward is 1.0 iff the extracted hypothesis matches a regex, 0.0 otherwise — deterministic in the policy's own text, no API models involved. Plotted value is rollout/raw_reward, which for a binary reward equals the fraction of the group that matched.

Run status

Only one run finished cleanly, and its clean exit was itself spurious. Every restart began a fresh run at step 0 — there is no checkpoint resume, so each preemption costs the whole run.

The genuine signal — single keyword

Matches are verified real: short hypotheses (max ~690 chars), zero truncation in either run. pottery form corresponds to a real dataset column (PotteryForm_inter), so this measures variable steering at a ~1–2% base rate.

At g256 the reward rose from 2/256 to 12/256 in three steps — a real ~6× climb, with response length falling (8.9k → 5.9k) while entropy rose, which reads as exploration rather than collapse. It was preempted before the trend could be confirmed.

At g16 the reward quantum is 1/16 = 0.0625, larger than the entire base rate, so nearly every group is all-zero and the apparent 1 → 3 rise sits well inside binomial noise. Group size, not reward design, is what makes the signal legible.

The hack — two keywords at g256

This run reached reward 1.0 and looks like a triumph. It is measuring a parser bug: reward tracks the truncation rate almost exactly, step for step.

Mean response length climbed monotonically from 8,642 tokens to exactly the 16,384 cap. When a response is truncated before its closing JSON, extract_hypothesis falls back to returning the entire response — which trivially contains both "pottery form" and "copper".

Evidence. Among reward=1 records the mean hypothesis is 57,075 characters (802 chars of reasoning); among reward=0 it is 452 characters (35,152 of reasoning). 501 of 510 scored successes had hypotheses over 10k chars — only 9 were real matches.
Read it the other way round: this is the strongest evidence in the whole suite that GRPO optimizes effectively. Given a mis-specified reward, it found the exploit within eight steps. The fix — score truncated samples 0, mirroring the guard the real reward path already has — is applied in keyword.py and awaiting a rerun. The real surprise-reward path was never affected.
